# 实现原理

这份文档说明「音频 → 触感」的思路、每个参数为什么这么定，以及走过的弯路。

---

## 1. 目标：震得"像"而不是震得"响"

B站的动感视频之所以不像"跟着节拍敲桌子"，是因为它复现的是**声音的质感**：

- 底鼓、贝斯 → 厚实、闷、一下一下的推
- 镲片、嘶声、火焰、风 → 细碎、发麻、像指尖擦过

如果只按"响度"驱动震动，这两者在触感上完全一样——都是"嗡"。
要复现差异，必须让**音色**参与映射。

## 2. CoreHaptics 只有两个自由度

苹果的触觉引擎看似复杂，能实时调的其实就两个维度：

| 参数 | 感知含义 | 数值大 → |
|---|---|---|
| `hapticIntensity` | 力度 | 更重、更实 |
| `hapticSharpness` | 频率/锐度 | 更高频、更"脆"、更"麻" |

所以问题被化简成：**怎么从音频里同时提取"力度"和"锐度"两条曲线。**

- 力度 ← 响度（能量）
- 锐度 ← 音色（频谱重心 / 高频占比 / 噪声性）

这就是整个设计的出发点。

## 3. 信号链路

```
音频文件
   │  AVAssetReader 解码
   ▼
22kHz 单声道 PCM（16bit）
   │  一阶低通 ×2，取差值
   ▼
三段能量：low(<120Hz) / mid(120~2k) / high(>2k)
   │  逐帧（1/60 秒）聚合
   ▼
每帧 6 个特征：flux, low, mid, high, brightness, noisiness
   │
   ├─────────────────────────────┐
   ▼                             ▼
【连续层】                     【离散重击】
响度 → intensity               flux 突增 → 起音点
音色 → sharpness               落在 BPM 网格上 → 加重
每帧推一次参数                 提前 4 秒排进 pattern
   │                             │
   └────────────┬────────────────┘
                ▼
           CoreHaptics
```

## 4. 特征为什么这么算

### 4.1 三段能量

用两个一阶低通做频段切分，避免上 FFT：

```
lowLP  = lowLP  + 0.034 · (x - lowLP)     // 截止 ≈ 120Hz
highLP = highLP + 0.35  · (x - highLP)    // 截止 ≈ 2kHz

low  = lowLP
high = x - highLP                          // 高通残留
mid  = highLP - lowLP
```

理由：触觉不需要频率分辨率，需要的是**包络**。一阶滤波的相位延迟小、算力极低，
60fps 实时推参数完全够用。

### 4.2 频谱通量（flux）

```
flux = max(low - 上一帧low, 0)
     + max(high - 上一帧high, 0) × 1.4
     + mid × 0.2
```

取"正向增长"而不是绝对值，是因为要抓**起音**（attack），不是持续音量。
高频权重 1.4 是因为镲、嘶声的起音能量远小于底鼓，不放大就淹没在低频里。

### 4.3 亮度与噪声性

```
brightness = (high × 1.6 + mid × 0.6) / (low + mid + high)
noisiness  = high / low × 0.35
```

- `brightness`：整体偏高频的程度，人声、镲片会高
- `noisiness`：高频相对低频的**富集**，宽带噪声（火、风、沙锤）会异常高

后者是"呲"的关键——火焰没有明确的音高，能量摊在很宽的频带上，
低频几乎没有，比值直接顶满。

### 4.4 响度归一化

```
reference  = 整曲响度序列的 95 分位
normalized = loudness / reference
```

用整曲分位数而不是峰值，是为了让**副歌真能顶到 1.0**，
同时不被个别爆音拉低整体。否则安静段落会把平均值拖垮，副歌永远到不了满。

## 5. 两层输出：为什么必须分开

**连续层**负责"质感"，**离散重击**负责"节奏"。两者缺一：

| 只有连续层 | 只有离散重击 |
|---|---|
| 永远在震，糊成一团 | 安静段落完全没感觉，像卡顿 |
| 没有"一下一下"的节奏 | 没有音色差异，闷和脆一个味 |

实测中，纯连续层会被评价为"糊"，纯离散会被评价为"空"。
所以最终是连续层铺底（权重可调，0 可关）+ 离散重击打点。

## 6. 时间同步：为什么要预排程

每帧现场 `makePlayer()` + `start()` 会有**几十毫秒的抖动**，
而人耳对节奏误差的容忍度约 20~30ms。逐个现场触发的结果就是"糊"。

做法：一次把**未来 4 秒**的所有重击写成 pattern 里的绝对时间事件，
交给引擎自己按点触发；播放中每 2.8 秒重排一次窗口。这样时间精度由引擎保证。

## 7. 参数的听感含义

| 参数 | 调大之后 | 典型用途 |
|---|---|---|
| `sensitivity` | 点变少，只留最重的 | 安静的抒情歌调高 |
| `minGap` | 点变稀 | 密集鼓点调高防糊 |
| `strength` | 每次更重 | 想要冲击力 |
| `sharpness` | 更脆 | 电子、摇滚 |
| `bed` | 连续层更明显 | 想要"推背感" |
| `floor` | 安静段也有震动 | 想要持续存在感 |

四档预设就是这些参数的组合：柔和 / 标准 / 强烈 / 超强。

## 8. 走过的弯路

这几条是实际调试中踩到的，写下来避免重复：

1. **只按响度震动** → 所有声音一个味，糊。加音色通道才解决。
2. **现场构造重击播放器** → 抖动几十毫秒，节奏散。改预排程。
3. **包络释放太慢**（每帧 ×0.82）→ 几十秒降不下来，糊成一片。改快起快落（每帧 ×0.6）。
4. **连续事件基础强度设 0** → `hapticIntensityControl` 是乘法，0 乘任何值都是 0，永远不震。
5. **`bed` 二次放大**（除以 0.4）→ 所有档位饱和到 1.0，"怎么调都一样糊"。
6. **`CADisplayLink` target 不是 NSObject** → `@objc` 方法挂不上，分析全对但一点不震。
7. **远程音频直接读** → `AVAssetReader` 读 HTTP 流解析出 0 帧。必须先落盘。
8. **临时文件丢了扩展名** → `AVURLAsset` 靠扩展名认容器，`.bin` 直接取不到音轨。

## 9. 局限与后续

- 现在用一阶滤波近似频段，分辨率有限。服务端可以上 STFT，用真正的
  谱质心、谱平坦度、谱通量，音色映射会更准。
- 客户端分析要先把整首歌下载到本地，首播有 1~3 秒空窗。
  服务端预生成时间轴可以彻底解决：一首 4 分钟的歌时间轴约 30 KB。
- 无法区分乐器语义（"这是小提琴还是合成器"）。要走到那一步需要音源分离。
